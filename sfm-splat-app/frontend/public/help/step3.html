SfM — cameras & sparse cloud

Purpose

Run spirula sfm auto over frames/: detect features, match them between overlapping images, solve every camera pose, and triangulate a sparse point cloud. The result is a COLMAP model in sfm/sparse/0/ that step 4 trains from.

Nothing is copied. The reconstruction is written beside the frames, and the training step reads the same frames/ directory — there is no second, undistorted copy of the images anywhere in this app.

Settings

SettingDefaultWhat it does
Quality high low / medium / high / extreme — moves the working resolution, the feature budget and the pair selection together. The run prints what the preset moved
Data type individual Individual photos / video frames / internet collection. Pick video frames for anything extracted from a rush
Camera model opencv Pinhole and radial variants, plus OpenCV fisheye, thin-prism fisheye and equirectangular (360°)
Camera mode folder How intrinsics are grouped — single, per folder, or per image
Pairs auto auto / exhaustive / sequential / prefilter
Use masks on Adopts masks/ automatically when it exists — it is already the sibling of the image directory, so it costs no flag
A knob left at its own default is not sent. Naming a flag explicitly overrides whatever the quality preset would have set for it, so only the values you actually moved reach the command line. That is why the panel shows the preset's own numbers rather than a frozen copy.
360° and fisheye need no undistortion pass. Name the lens in Camera model and the reconstruction reads the frames as they are.

The mask pass

A panel of its own on this step, re-runnable without touching the reconstruction, and it never marks step 3 done or failed — masks are an input to the alignment. Its output is masks/, which both this step and the training step read.

ModeWhat it masksCost
Off Nothing — or whatever step 2's alpha extraction already wrote —
Shape The part of every frame that is never scene: a fisheye border, a watermark, the rig in shot. It is a shape, not an object, so it needs no model free — no download, no licence question, 238 frames in about 2.6 s
Track Named objects, from a text prompt — "mask out the people". Prompted objects come out black and everything else white, which is what a reconstruction wants needs a SAM checkpoint, installed from Setup → Checkpoints

Shape masking is safe to run speculatively: on rectilinear frames with no border it answers "no border found" and writes nothing. Without Replace, a run intersects with the masks already there, so it stacks on top of a tracked pass rather than overwriting it.

SAM 2.1 is Apache-2.0; SAM 3 is Meta's own non-standard licence. They are two separate acceptances in Setup → Checkpoints, and nothing is fetched before the matching one is given.

Reading the result

FigureWhat to look for
registeredimages placed / total. 100 % is the target
reprojectionmean and median pixel error. Well under 1 px on a healthy run
pointssize of the sparse cloud
camera groupsdistinct intrinsics. More than one is normal when the frames are not all the same resolution — it is not a split reconstruction
modelsthis is the one to watch. More than one means the capture did not connect into a single view graph

Exit codes

CodeMeaning
0A reconstruction that looks sound
1Usage or runtime error
2No reconstruction at all
3Partial — under half the images registered, or over 2 px mean reprojection
Exit 3 warns and does not fail the step. Blocking the pipeline over a handful of unalignable frames is the wrong call — the number is named, and whether to re-run is yours.

The viewer

The sparse cloud with the camera overlay on top: one frustum per solved camera, coloured per sequence, with the path breaking at each cut. Each frustum is drawn at the lens the reconstruction actually solved. This is where a folded camera path, a component at the wrong scale, or an orbit that never closed becomes obvious.

Curation verdicts are advisory here. This step reconstructs everything in frames/, including frames step 2 marked rejected — there is deliberately no filtered second copy. Use Delete in step 2's gallery if you want a frame gone for real.

Output

sfm/ — the features, the matches, sparse/0/ (COLMAP binary: cameras.bin, images.bin, points3D.bin) and a result file recording the exit code, the registered count and the reprojection error.

Re-running this step deletes the whole sfm/ workspace first — including depths/ and normals/ if the geometry pass of step 4 has written them, since they are per-image maps of this reconstruction. masks/ is left alone.

Troubleshooting

  • More than one model — the capture broke into disconnected pieces. Look for the gap warnings in step 2, and prefer video frames as the data type.
  • Few images registered — usually too little overlap, or heavy motion blur. Extract at a higher fps and re-run.
  • A 360 capture reconstructing badly — check the camera model is equirectangular or the right fisheye, not opencv.
  • Slow — extreme quality raises the working resolution and the feature budget substantially; medium is often enough.

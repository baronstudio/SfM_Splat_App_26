Extract frames & curate

Purpose

One job, two phases. Extraction writes frames/ with FFmpeg — the image directory every later step reads. Curation then scores those frames and marks the ones worth keeping.

The two phases are separable on purpose: Re-analyse re-runs the curation over the frames already on disk. Tuning a threshold must never cost a re-extraction.

The source panel

Before anything runs, the step lists what input/ holds: each file with its container, codec, resolution, fps, duration and a poster frame — pulled a tenth of the way in, because frame 0 is the operator still reaching for the camera. The video the extraction will consume is badged.

Working fps policy

ModeMeaning
autotarget frames ÷ duration, clamped to the preset's bounds
ratioa fraction of the source fps — default 0.2, so 20 img/s on a 100 fps rush
absolutea literal fps you type
An fps too low to place even one frame inside the clip is refused before anything is deleted, naming the fps that would work — FFmpeg does not write zero frames, it fails. The estimate beside the setting turns amber at the same threshold.
Hardware decoding is an installation setting, in Setup → Tools, not a per-project one: it describes the GPU in this machine. It is worth having — on 4K HEVC it took an extraction from 95 s to 18 s. If the driver refuses it, FFmpeg falls back to software and the run says so on the line where it happens, in the log.

Image sets instead of a video

When the source is an imported set the step conforms rather than extracts, and the result is indistinguishable downstream. Every image is a frame: the fps policy does not apply and is hidden, and Max frames is the only gate. At 100 % scale with a matching format the frames are hard-linked rather than re-encoded — re-encoding a JPEG is generation loss for no gain.

If the set is PNG with a real alpha channel, the step asks — inline, beside the estimate it changes — and extracts that channel into masks/.

Curation

Four passes, in order:

  1. Scenes — each cut splits the footage into a sequence. The scores are captured by the extraction itself, on frames it was decoding anyway, which is what took a 52 s rush from 318 s of detection to about 5 s.
  2. Sharpness — Tenengrad on greyscale. Rejection is relative, against a rolling 15-frame median, never an absolute threshold — an absolute one does not generalise across content.
  3. Overlap — per sequence, the median feature displacement against the last kept frame. Below 2 % of frame width → redundant; inside 2–12 % → keep; above → keep, flagged gap.
  4. Select — the verdicts merge into a selection, and your manual overrides always win.

Reading the result

  • The summary row: kept / total, removed, and the split by reason — blur, redundant, gaps.
  • The sharpness timeline, with a marker at every detected cut.
  • The frame gallery, with each frame's verdict and a manual keep / drop override. Overrides are never regenerated by a re-analysis.
A verdict is advisory. Step 3 is handed the whole frames/ directory, so a frame marked rejected:blur is still reconstructed. Only Delete in the gallery actually removes one. Step 3 repeats this where you can see it.

Output

  • frames/ — the image directory, frame_0001.jpg onwards.
  • analysis/ — the probe, what the extraction did, the per-frame scores, the selection and your overrides.
  • masks/ — only if an alpha channel was extracted.

Troubleshooting

  • FFmpeg not found — set its path in Setup → Tools.
  • Far too few frames — check the fps mode; absolute left at a small value on a long clip is the usual cause.
  • Nearly everything rejected as blur — lower the sharpness sensitivity and press Re-analyse; nothing is re-extracted.
  • A cut where there is no cut — an invented cut resets the overlap gate mid-shot. Force the cut source to the frames, or raise the threshold, and re-analyse.

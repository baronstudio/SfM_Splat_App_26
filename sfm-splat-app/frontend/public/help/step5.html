Mesh extraction & delivery

Purpose

Run spirula mesh to extract a surface from the trained Gaussian splat and colour it from the cameras solved in step 3. Then fill export/, the delivery drawer. The pipeline ends here.

It meshes the crop when there is one. If step 4's crop was applied, that is the file this step reads — a mesh of the trimmed scene and a mesh of the whole room are the same command and very different results, so the panel and the log both name which file was used.

Formats and colour — the one enforced pair

FormatColour it can carry
GLB defaultTexture inside the file. The only one the viewer here can open
glTFTexture beside it, as separate files
OBJTexture only — OBJ carries no vertex colours
PLYVertex colour only — PLY carries no texture
An impossible pair — PLY with a texture, OBJ with vertex colours — is refused before the run and the button is disabled on it. This is not fussiness: the tool does not skip the offending format, it exits having written nothing at all, not even the GLB it could have made. Losing a several-minute mesh to that is worth one disabled button.

Settings

SettingDefaultWhat it does
Colour vertex None, vertex colour, or a baked texture atlas. The atlas looks far better and is the slowest phase of the run
Texture size auto 0 lets the tool pick from the texel density it measured. The run reports the size it chose and the coverage it achieved
Texture encoding png PNG, or JPEG at q95 / q75 for a much smaller file
Use cameras on The cameras decide occupancy and colour. Off meshes from the Gaussian densities alone — a fallback, not an improvement
Max grid resolution 512 The detail ceiling of the extraction, and the main cost knob
Cull unseen on Drops surface no camera ever saw. It leaves open boundaries — which is why the viewer draws both sides of every face
Floater minimum faces 100 Removes small disconnected islands
Quality iterations 3 Passes of the mesh cleanup

Reading the run

The log names each phase — loading, point cloud, Delaunay, occupancy, cut edges, bisection, marching tets, merge, cull unseen, cleanup, quality, orient, texel density, UV, bake, colour, texture. Three of them render every camera in turn, and those are the long ones.

Some phases report no number at all, so the bar rests on that phase's floor instead of inventing a percentage inside it. A step that has been running with no progress message switches to indeterminate stripes and an elapsed count — "31 %, and nothing since" is more use than a frozen bar.
FigureWhat to look for
vertices / facesThe size of the surface
componentsDisconnected pieces. A high count means floaters survived — raise the floater minimum
textureThe atlas size the run chose
coverageHow much of that atlas carries real texels. Very low coverage means the size was larger than the surface needed

The viewer

The mesh loads as it was written — there is no decimated preview, because a textured GLB is already small next to the splat it came from. A wireframe toggle draws the triangles: a surface that looks solid and a surface that is solid are the same picture until you see the edges.

Only glTF is shown. A PLY-only mesh would be read as a plain point cloud and drawn as its vertices — a different picture, not a cheaper one.

The delivery drawer

The second half of this step fills export/ with the splat it meshed and the mesh it wrote. They are hard links, not copies — the splat can be hundreds of megabytes and there is no reason for a second set of the same bytes.

That is safe both ways round: resetting step 5 drops the drawer and leaves the training output, resetting step 4 drops the training output and leaves the drawer holding the bytes. Nothing in the app ever writes into an exported file.

For a reduced or compressed splat — SOG, SPZ, .splat, an SH-cut PLY, with the saved viewpoint attached — use the export panel at the bottom of step 4 instead. That one is a deliverable; this drawer is the pipeline's own output.

Output

  • mesh/ — mesh.glb / .gltf / .obj / .ply, and the run's own result record.
  • export/ — splat.ply and the mesh files, as links.
Re-running this step clears both directories before it writes a byte.

Troubleshooting

  • The run is refused before it starts — an impossible format/colour pair; the message says which.
  • Holes in the surface — Cull unseen removed geometry no camera saw. More coverage in the capture is the real fix; turning the cull off trades holes for invented surface.
  • Thousands of components — floaters in the splat. Crop them out in step 4, or raise the floater minimum.
  • The mesh includes the whole room — the splat did too. Crop in step 4 and re-mesh; this step will read the crop.
  • Very slow — the texture atlas and the camera loops dominate. Vertex colour, or a lower grid resolution, is much faster.

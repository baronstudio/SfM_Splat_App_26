Training — the Gaussian splat

Purpose

Run spirula train on the cameras from step 3 and the frames from step 2. The output is splat.ply — hundreds of thousands of coloured Gaussian primitives — plus three optional passes on the same page: geometry before the run, crop and export after it.

Spirula trains through Vulkan. It runs on the discrete card, and it runs on integrated graphics too — there is no CUDA requirement anywhere in this app. The gauges in the left column show which device is actually working.

Presets

The preset is the first thing chosen, and it moves the defaults of everything below it — so the panel always shows the selected preset's values, not a frozen copy of another one's.

Key settings

SettingNote
Iterations 30 000 is the usual full run. A 30 000-step run on a 238-frame project measured about 16 minutes on this class of machine; a few hundred steps is enough to check the framing
Max splats The cap. If the run reaches it, the panel says so — the picture is being limited rather than converged
SH degree Spherical harmonics — view-dependent colour. Degree 3 is the usual; it is also about three quarters of the file size, which the export panel below can drop
Use masks On when masks/ exists. Masked pixels are trained as empty, which removes the background and leaves the subject — the merely "ignore" behaviour is measurably indistinguishable from no masks at all, so it is not offered
Use depths / normals On when the geometry pass has written them; otherwise the step explicitly tells the trainer there are none rather than pointing it at an empty directory
A knob left unset means "the preset decides", and it stays off the command line. The log and the result record what the run resolved to either way.

The geometry pass (optional, before training)

spirula geometry writes a per-image normal map — and optionally a depth map — into the SfM workspace, where the trainer picks them up by name. It is off by default, it is re-runnable on its own, and it never marks the step done or failed.

  • Depth is off on purpose: normals are what a reconstruction usually wants, and depth doubles both the disk cost and the reading the training does.
  • An aborted pass is cheap to resume — without Overwrite, a new run continues where the last one stopped.
  • It needs a geometry checkpoint. Install one from Setup → Checkpoints first; otherwise the first run downloads several hundred MB in the middle of the pass.
Changing the normal format writes the new maps beside the old ones rather than over them. The run counts the leftovers of the other format and names them — which of the two the trainer then reads is not something to leave to chance.

Reading the run

The progress line carries step N/M, the live splat count, an ETA, and rgb_loss, ssim, psnr. The bar maps the step count onto 5–95 %: a run loads its dataset before step 1 and writes a checkpoint after the last.

The live splat count is not the count in the file. The final prune runs after the last progress line, so a run that printed a million can write appreciably fewer. The result panel shows both: the live count, and the real count read off the written PLY.

The viewer, the crop and the saved view

The trained splat renders here, sorted and alpha-blended. Three things live on it:

  • Crop volumes — add boxes and spheres, drag them with the gizmo, and mark each one keep or delete. The rule is (inside a keep volume, or there are none) and (inside no delete volume), so delete always wins and a single delete sphere is a complete crop. Up to eight volumes.
  • Live cut — the preview hides what the volumes exclude, in real time. It is only a preview.
  • Save view — stores the camera exactly as it stands. A splat has no front; this is how the export ships with one.
The live cut is not the crop. Nothing on disk changes until you press Apply crop, which writes a separate train/crop/splat.ply beside the trained one — so a crop is undone by deleting one directory, and a re-crop always starts from the full splat. The panel warns when a crop is stale (the volumes moved since it was applied) and the export warns when volumes are placed but never applied.

Step 5 prefers the cropped file when there is one, and says which file it got.

The export panel (the last thing on the page)

A deliverable copy of the splat, for a web viewer, a client or a phone. It is the opposite of the crop: nothing in the pipeline reads it. It lands in train/export/ and step 5 never sees it.

Reductions — every one ships off

  • SH degree 3 → 0 drops all 45 harmonic coefficients: about 3.6× smaller with no geometry loss at all. The single best trade in the list. 3 → 1 keeps some view-dependence at 2.4×.
  • Opacity floor — not free housekeeping here. Spirula trains at low opacity by design, so the 1/255 threshold other toolchains ship drops around 1 %, and anything high enough to matter is an edit of the picture (0.05 dropped 43 %).
  • Target count — keeps the most important gaussians, scored by opacity × volume. The score is approximate and labelled so, and nothing is re-fitted afterwards: a deep cut thins the picture rather than simplifying it.
The saved view rides out with the file: a .ply carries it in its header, and every other format gets a small .viewpoint.json beside it.

Output

  • train/run/step-*.ckpt/splat.ply — the trained splat. One checkpoint survives a run by default.
  • train/crop/splat.ply — the cut, when Apply crop was pressed.
  • train/export/ — the deliverable copies and their sidecars.
Re-running the training deletes all three — they are all derived from a splat that is being replaced. The crop volumes, the saved view and the export plan survive: they are stored on the project, and the frame they are expressed in comes from the SfM model, which a re-train does not touch.

Troubleshooting

  • The masks appear to do nothing — check the mask count in the log. A mask directory that is empty or wrong trains unmasked and still exits 0, which is exactly why the count is printed.
  • The run hit the splat cap — raise Max splats, or accept it; the panel says which happened.
  • Low psnr — look back at step 3. A poor reconstruction cannot be fixed by more iterations.
  • The scene looks cropped but the export is full-size — the volumes were never applied. Press Apply crop.
  • Out of video memory — lower the training quality or the max splats, or extract at a smaller scale.

📖 Spirula Wizard — Help

Home 1 · Import 2 · Extract 3 · SfM 4 · Train 5 · Mesh

Spirula Wizard is a five-step local workflow that turns a video or an image set into a 3D Gaussian Splatting scene and a textured mesh, ready for web or engine import.

It drives two binaries and nothing else: ffmpeg for everything before the reconstruction, and spirula.exe for the reconstruction itself. Spirula is Vulkan, not CUDA — the pipeline runs on NVIDIA, AMD, Intel and Apple silicon alike.

Pipeline overview

# Step Tool Output
1 Import — Source video or image set in input/
2 Extract frames FFmpeg frames/, analysis/, and masks/ from an alpha channel
3 SfM spirula sfm auto Cameras + sparse cloud in sfm/sparse/0/
4 Training spirula train Gaussian splat in train/run/step-*.ckpt/splat.ply
5 Mesh spirula mesh Textured mesh in mesh/, delivery drawer in export/

Five more passes hang off the steps rather than being steps of their own, because each can be re-run alone without redoing the expensive work above it: curation (step 2), masking (step 3), geometry, crop and splat export (step 4).

Quick start

  1. Pick New Project from the project menu in the top bar and give it a name.
  2. Import a video or an image set in step 1.
  3. Walk steps 2 → 5 in order; each one checks its input before it runs.
  4. Watch the Live Log at the bottom and the progress bars on the step.
  5. Abort in the top bar stops a running job — it kills the tool's whole process tree, so nothing is left running behind it.
Re-running a step resets that step and every step after it before it writes anything. input/ is never a casualty.

Interface layout

  • Top bar — Home, project menu, step counter, app version, setup (gear), Help and Live Log toggles, Abort.
  • Left column — the step navigator, the Project info panel (footage author, description and a recap of the project row), and the live CPU / GPU / VRAM gauges pinned under them.
  • Centre — the active step: its settings, its Run button, its results and, from step 3 on, the 3D viewer.
  • Right — this Help panel, which follows the step you are on.
  • Bottom — the Live Log, fed over a WebSocket while a job runs.

The 3D viewer

Steps 3, 4 and 5 each show their own output — the sparse cloud with the camera overlay, the trained splat, the textured mesh. The viewer never writes to the reconstruction; the one thing it places is the crop volumes of step 4, and the cut itself is made server-side into a separate file.

Common controls: a level selector (a decimated preview, or Full), Flip up for a capture the mapper levelled on the wrong vertical, reframe, and fullscreen — the wizard column is too narrow to judge a scene in.

Spirula Studio — the tool behind steps 3 to 5

One binary, spirula.exe, carries six tools. This wizard drives five of them from the command line — sfm, train, sam, geometry, mesh. The sixth is gui: Spirula Studio's own graphical editor, which is what you get by running the binary with no command at all.

  • spirula — open the editor.
  • spirula <file-or-folder> — open a splat, a checkpoint or a dataset directly in it.

The binary is wherever Setup → Tools points; by default tools/spirula/spirula.exe under the app.

The wizard never launches the editor, and it explicitly disables the trainer's own built-in viewer on every run — left enabled, a finished training run never exits, and the viewer binds every network interface rather than just this machine. Opening a result in the editor afterwards is a separate, manual thing, and a perfectly good one: train/run/step-*.ckpt/splat.ply or train/crop/splat.ply will open straight in it.

Every invocation from this app pins English output, because the tool localises its progress lines and the parsers here read English. The editor itself speaks thirteen languages, French included — that is a property of how you launch it, not of the build.

The installed version is read, never remembered: spirula --version is logged at the top of every run and recorded in that step's result, so a result always says which build produced it. Upstream: github.com/harry7557558/spirula-studio.

Settings — three layers

LayerWhereWhat
Installation config.json Binary paths (spirula, FFmpeg), hardware decoding, the checkpoint cache
Defaults defaults.json Business defaults for every step — what a new project starts from
Per project the project row Only the keys you changed for this project

Precedence is project > defaults > code. A project stores only its own overrides, so changing a default still reaches every project that never touched it.

There is no Save button anywhere. Every panel saves as you type — debounced, and flushed when you leave the panel, switch project or close the tab. The small "Saving… / Saved" hint beside a panel is the confirmation.

Application setup (the gear icon)

One section per wizard step — Extraction, Curation, SfM, Masks, Geometry, Training, Mesh, Export, 3D viewer — plus three that are properties of this machine rather than business defaults:

  • Tools — where spirula.exe and ffmpeg live, and hardware decoding.
  • Checkpoints — the SAM and geometry neural weights: downloaded, resumed, verified against the manifest compiled into spirula.exe, and installed into spirula's own model cache. Each family's licence is shown and accepted separately before anything is fetched.
  • Hardware — CPU, memory and every graphics adapter, with spirula's own Vulkan verdict on each. Read-only, so it has no Save and no reset.
spirula.exe and FFmpeg must both be resolvable before any step will run. Checkpoints are optional: SfM, training, meshing and shape masking need none.

Project lifecycle

The ⋮ menu on each project tile, all refused while that project has a job running:

ActionWhat it does
CopyDuplicates the directory and the row under a new name — settings, crop volumes and saved view included
ResetDeletes the artefacts of a step and of every step after it. Never input/
ArchiveZips the directory away and keeps the row disabled until it is restored
DeleteRemoves the row, the directory and the archive
A copy or an archive moves gigabytes and cannot be aborted — there is no child process to kill. It runs behind a dialog that nothing dismisses until it is finished.

The neural checkpoints — four separate questions

Weights are never bundled: spirula.exe carries no model data. Setup → Checkpoints shows each family's terms and requires the matching acceptance before it will fetch anything, and the download route re-checks that acceptance rather than trusting the panel.

Every dependency is justified and carries a row in the project's own audit table before it is added — there are no unlisted ones. The hardware panel and the gauges, for instance, cost nothing at all: they read documented Windows facilities directly rather than pulling in a monitoring library.

What this app deliberately does not depend on: no CUDA, anywhere. Not in the reconstruction, not in the export path — a Python library that would have made SOG export easier was refused for importing a CUDA package. That is the whole reason this pipeline runs on AMD, Intel and Apple silicon as readily as on NVIDIA.
